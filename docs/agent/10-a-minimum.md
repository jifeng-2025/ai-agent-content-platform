# A：可靠创作最小闭环
任务范围：A1/A2；A3 可靠性设计见 20-content-runtime.md，仅涉及该项时补读。

## 目标与边界

现有标题选择、大纲确认、正文和配图链保持可用。A 不做联网 Research、向量数据库、长期记忆或新增生图平台。A 对无依据事实做风险提示/删除/限定表达，**不承诺事实核查**。

```text
大纲确认 → Writer → Reviewer
                     ├─ PASS → 现有配图 → 合成 → 人工预览
                     ├─ REVISE 且有预算 → 局部修订 → Reviewer
                     └─ 达到上限/证据不足 → NEEDS_REVIEW（保留正文）
配图失败 → 显示缺图/降级 → 用户单图重试（不重跑正文）
```

## A1：后端 Loop

主入口为 agent/ArticleAgentOrchestrator.java、agent/agents、model/dto/article/ArticleState.java（路径相对 src/main/java/com/yupi/template）。先追踪 Controller 到实际服务，确认 orchestrator 开关和旧 ArticleAgentService 的关系。

- 新增 ReviewResult：schemaVersion、decision(PASS/REVISE/NEEDS_REVIEW)、issues[{type,severity,sectionId,reason,suggestedAction}]。
- 检查受众匹配、篇幅、结构、无来源的精确数字与机构归因；程序校验 Schema，规则能判断的事项不完全依赖模型评分。
- 修订只输入目标、当前稿件、相关问题和用户确认的大纲；保留不可改部分与版本。
- Runtime 独立限制 maxRevisions=2。第 0 版评审不计修订；最多产生第 1、2 版，仍不通过则交人工处理。
- 无效结构化输出、模型超时、重复问题无进展有明确出口。费用/轮数约束不可由模型覆盖。
- 新循环用配置开关启用；旧接口和 SSE 事件保持兼容，新事件字段做增量扩展。
- 固定桩测试覆盖首次通过、一次修复通过、两次仍失败、非法输出、模型失败。不要为成功测试调用真实收费 API。

## A2：前端可见反馈

沿用 frontend/src 页面，不重做整站。新增：
- 当前阶段、修订轮次、问题列表、版本对比与“待人工处理”状态。
- 接受当前稿件/修改后重试的交互；不能暗示未核查事实已被验证。
- 配图来源及降级标记；Picsum 是随机占位图，不算图文语义匹配成功。
- 单图重试保留正文；用户确认、取消和失败路径均可观察。

验收覆盖桌面/手机视口、长文章、错误状态、重复点击。每次至少提供实际操作记录、console/network 错误检查及已检查截图；截图生成本身不算验证。

## A3：可靠性最低交付

在20模块约束下实现持久阶段状态、外部请求幂等、SSE重连去重、取消和超时。重启恢复以已完成阶段为边界，不要求从生成到一半的 token 精确续写。默认单任务串行执行。

## A4：A 完成门槛

以下全部通过后才能进入 B：
1. 正常创作仍可运行，能查看并导出图文。
2. 至少一个受众/结构缺陷触发修订并改善，有前后版本。
3. 超过两轮明确转人工，不无限循环、不伪报完成。
4. 配图失败保留文章，单图重试不会重新生成整篇；降级状态明确。
5. 中断恢复测试能从已保存阶段继续，重复请求无重复副作用；不确定外部结果先查询。
6. H0 已形成可重复的“改动→测试→运行→浏览器验证→修复→回归”步骤与产物。
7. 5 个固定案例有 baseline/当前结果；真实 API 冒烟与 Mock 回归分开标记。
8. 在现有 Compose 上验证升级，保留数据；文档清楚写明失败与回滚方式。
