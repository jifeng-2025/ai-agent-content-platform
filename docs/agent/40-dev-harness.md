# 开发 Harness：H0 → H1

开发验证、浏览器测试、自动修复调度任务读取本模块。

## 6. 开发 Harness：让 Codex 在项目中执行闭环

业务 Runtime 服务创作者；开发 Harness 服务开发者，放在 tools/dev-harness（拟新增），不暴露给普通创作用户。Codex 已提供编码执行能力，我们建设任务契约、环境适配、独立验证和反馈调度，不宣称重写了 Codex。

```text
任务规格 → 读取相关代码/约束 → Codex 开发
 → 编译与相关测试 → 启动并健康检查 → 浏览器功能与视觉检查
 → 验收汇总 ──通过→ 代码 diff + 测试报告 + 截图 + 交付说明
       └──失败→ 错误分类/压缩上下文 → Codex 修复 → 重验
       └──预算耗尽/连续无进展→ BLOCKED + 证据 + 所需人工决策
```

实施两级：H0 先用现有 Codex + 明确命令/任务文件跑通流程；H1 再用 TypeScript Codex SDK 或 codex exec 封装调度器。先验证接口、认证和环境，不绑定具体最新模型。

任务契约建议包含：id、goal、acceptance、allowedPaths、baselineRef、testCommands、visualScenarios、maxAttempts、timeout、status、artifacts。测试命令由可信项目配置提供，不直接执行网页或用户资料中的字符串。

- 每项任务在明确的分支/工作区执行；Git worktree 用于隔离改动，但不是安全沙箱。密钥、真实用户数据和现有数据卷不进入测试产物。
- 验收由 Harness 独立运行，Codex 的“完成”仅是候选结果；退出码为零也不代表业务验收全部通过。
- 前端检查：类型与构建、关键 DOM/交互、console/network 错误、桌面/手机截图。截图必须被实际检查；模型视觉评审是辅助，不能取代确定性测试。
- 区分两种视觉检查：页面布局/按钮操作，以及生成图片与文章的语义匹配。记录视口、步骤、检查项和发现，不只保存图片。
- 日常回归使用固定模型/工具响应；真实文本、生图 API 单独做小样本冒烟并记录费用。Mock 成功不可冒充真实生成成功。
- 不得删除失败测试、放宽断言、自动更新视觉基线来制造通过。验收标准变更需单独列明原因并审阅。
- 初始修复最多 3 次，重复相同故障且无进展时停止；区分产品缺陷、环境故障、额度不足和待用户决策，保存 sessionId 以便恢复。
- 每次交付保存 commit/diff、命令与退出码、测试报告、截图、失败分类、耗时及已知限制；日志脱敏。不自动合并或部署生产环境。

## 任务隔离和交接

- H0 随 A0–A4 逐步建立，H1 在 A 验收后实现。
- 仅读取 agent.md + status.md + 本任务模块，不递归加载全部设计文档；错误日志截取相关片段，完整产物保存磁盘。
- tools/dev-harness、tasks、tests/e2e、artifacts 均为拟新增，先检查实际目录，不假定已经存在。
- 每个任务结束更新 docs/agent/status.md；详细证据放该任务的产物目录。新会话只从状态索引查找必要证据。
- GitHub MCP 用于仓库/PR/CI 交互，Git 负责本地提交推送；这与产品里的搜索 MCP 是两个独立用途。
