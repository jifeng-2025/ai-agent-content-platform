# B：可溯源研究创作扩展
前置条件：A4 通过。保留 Java/Vue/MySQL/Redis；以下只在对应任务读取。

## B1：研究工具与证据引用

- 增加需求/受众解析、研究计划、search/read 工具；按预算补检索，工具调用最多12次作为初始值。
- 保存 Evidence：id、URL/文档ID、标题、片段定位、抓取时间、摘要；Claim 关联证据ID与稿件段落。
- 正文引用可点击查看原始支持片段。引用可解析和证据能支持论断分开检查。
- Reviewer 输出补检索/修改段落/删除无依据论断等 action，由 Runtime 校验并路由。
- 事实不足必须提示或转人工，不能编造引用。搜索失败仍保留草稿。
- 在20模块既有检查点、限额、归属校验和事件结构上扩展，不能另外维护一份脱节状态。
- 验收：10个固定研究案例，包含冲突来源、无结果、陈旧资料和恶意网页指令。

## B2：小资料库 RAG + 偏好记忆

解析 → 分块 → 检索 → 引用；先关键词基线，再用同一评测集比较向量/混合方案。Embedding 默认云端；MySQL保存业务/元数据，向量接口按实测选实现，不为pgvector迁移数据库。

按需构建上下文：只给当前任务相关片段，限制检索数量、片段长度与历史摘要。偏好记忆只存用户确认的受众/语气/篇幅等，可查看修改删除。用户文章修订不自动变成全局事实或训练标签。

验收：引用定位正确；不同用户资料隔离；偏好可修改删除；检索指标按60模块测量。

## B3：产品 MCP

选择一个已运行的搜索或资料工具，接入 MCP client/server 边界；明确工具 Schema、鉴权、超时、返回值和失败处理，记录一次真实协议调用。

产品 MCP 用于创作 Agent 工具扩展；开发环境 GitHub MCP 用于代码/PR/CI。两者不能相互冒充简历成果。

验收：普通接口与MCP接入的同一用例结果可对照；权限拒绝、断连、非法参数有测试。不要为了接MCP重写所有工具。

## 产品最终效果

主题/资料 → 按需研究 → 大纲确认 → 证据驱动写作 → 评审/补证据/局部修订 → 配图与语义检查 → 人工预览/导出。角色为模块，可复用同一模型，不强制多服务多Agent并行。
