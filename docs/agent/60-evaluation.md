# 评测与简历证据

仅在测试集设计、对比实验、指标或简历整理时读取。

## 9. 评测与简历证据

内容集先 20 个主题（科普、技术说明、资料型文章），保留 5 个未用于调 Prompt 的案例；控制模型版本、输入资料、预算和运行环境，报告样本量及失败案例，必要时重复运行。

| 指标 | 口径 |
|---|---|
| 任务完成率 | 满足预先定义的交付要求的任务 / 总任务；失败、超时计入分母 |
| 引用支持率 | 人工/评审抽样中有充分证据支持的可核实论断 / 抽样可核实论断；同时报告引用覆盖率 |
| 内容符合度 | 按受众、结构、篇幅、图文一致性评分；展示评分规则，模型评分配人工复核 |
| 恢复成功率 | 故障注入后恢复且无重复副作用的任务 / 故障注入任务 |
| 成本与延迟 | 每任务 token、文本/图片/工具费用、总耗时；区分估算/实际，报告中位数与样本范围 |
| 开发闭环通过率 | 独立验收通过的开发任务 / 全部尝试任务，同时报告人工介入次数、修复轮数 |

简历主线（实施完成后再改为完成时态）：

1. 在开源图文平台基础上设计证据驱动的研究与创作闭环，通过工具检索、结构化评审和局部修订改善内容可核验性。
2. 实现任务状态、持久化恢复、工具幂等、预算与执行追踪，并用故障注入验证可靠性。
3. 构建基于 Codex 的开发 Harness，串联需求、开发、运行、浏览器视觉验证与测试反馈，交付可追溯的验收产物。

保留上游来源、许可证与作者信息；区分原有功能、个人新增模块和框架能力。提升百分比、QPS、成本节省、自主成功率一律来自实测；截图文章里的数字不是项目性能数据。

## A 阶段额外要求

A 先使用 5 个固定案例：受众偏离、超长、无依据数字、配图失败、任务中断。未接入真实检索前不能声称完成事实核查；无证据论断只能标记、删除、弱化表述或交人工处理。引用相关指标在 B 接入证据后测量。

对比原始 baseline 与当前版本，记录模型/Prompt/代码版本和样本量。公开案例仅使用可发布的测试资料。开发 Harness 通过率与文章质量分开报告。
